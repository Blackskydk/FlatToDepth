## Hardware acceptance

1. Connect Steam Frame to PCVR and wear the headset. Start `scripts/run.ps1 -Test` from the project. Look for the red single marker in the left eye and cyan double marker in the right. Orange block should be nearer than blue; the grid should fuse without vertical disparity. Verify the window stays fixed when looking around.
2. Start Ori normally through Steam, then `scripts/run.ps1` for the real feed. Keep Ori focused on the desktop for controller input. Confirm both eye views and stereo ordering; test `swap_eyes` if depth is reversed. Stop/restart FlatToDepth after INI changes.
3. Play a scene with foreground, gameplay and distant background; check halos, fog, water, lights, distortion, HUD, menus and cutscenes. Tune Geo-11's separation/convergence/HUD controls. Do not infer geometry quality from a pixel-difference count alone.
4. Change Ori's window resolution, minimize/restore, and restart the game. Check mapping reconnection, swapped textures, descriptor logs and regenerated eye swapchains. Verify no stale old frame remains. Handle reuse without generation metadata is a documented unresolved risk.
5. Check frame pacing while playing normally. `CPU_wait_and_submit_ms` includes runtime pacing and is not GPU rendering time. Inspect SteamVR frame timing for compositor misses; an idle headset with zero layers is normal and not a capture failure.
6. Watch for tearing or mismatched stereo instants. The legacy producer exposes no verified fence/frame ID, so synchronized frame delivery remains unproven. If visible, implement a synchronized exporter before claiming a stable MVP.

7. Window controls, worn headset, `scripts/run.ps1 -Test` or the real feed. Point a controller at the game: nothing should appear. Point just under it: the bar and the handle at the bottom-right should fade in; pointing away should fade them out within a moment. Aim at the bar: it highlights and a laser appears. Hold trigger, then grip, on the bar and sweep the window around you, then push and pull the thumbstick: the window should follow the laser, face you, and move further/closer without winding up at the limits. Drag the handle: the window should grow from its middle to both sides and stay in place. Confirm Ori ignores that controller (no jump or ability) while its laser is on the UI, that the other controller still plays, and that the saved placement survives a restart. Check the laser origin and direction against the real controller; if it is off, the log will say whether aim or grip pose is in use. Tune `[ui] push_pull_rate` if the thumbstick feels too fast or slow.
8. Ultrawide framing and launch from the headset. With Ori running on an ultrawide desktop, the window should show only the game (no black side bars) and the bar and handle should sit right under and beside it. On the first run after this change the log should say `Saved width_m covered the whole export` and the window should look the same size as before. Then set the Steam launch option from docs/INSTALL.md, close both Ori and the bridge, launch Ori from the SteamVR dashboard library, and confirm the bridge starts once Ori has a window, the picture appears in the headset, controller input works without clicking Ori on the desktop, and the bridge exits a few seconds after you quit Ori. `logs/launch.log` explains any run where it did not start.
9. Two games and the menu. Close both games and the bridge, run `./scripts/run.ps1`, and put the headset on: the menu should be in front of you with both games (log: `Game menu texture uploaded`). Point at a tile: it highlights and a laser appears. Pull the trigger on Will of the Wisps: Steam should start it, the menu should say it is starting, then the game should appear with correct depth (if inside-out, flip `swap_eyes` in `flattodepth-wotw.ini`). Check the controllers work in its menus (`game_XInput_reads` in the log) and that the black bars are cropped (`crop_aspect`; if the picture is cut, set it to 0). Resize and place the window, quit the game, and confirm you land back on the menu, then start Blind Forest from it and confirm it keeps its own size and placement. Also check a game started from Steam directly while the menu is up is picked up, and that the greyed-out state appears for a game that is not installed.

11. The games catalog and menu with a real Steam library. On the PC, run `bin\FlatToDepth.exe --scan` and check it lists your installed games, says the Ori games are supported, and shows plausible bitness, graphics and controller DLLs for a few games you know (a DirectX 11 game should read DirectX 11). Add a game you have a Geo-11 fix for to `games.user.ini` (`--scan --draft <app>` gives the start), run `Install.cmd -Games <id>`, and check the shim is placed (and the fix, if you gave a `fix_url` with its hash). Start FlatToDepth: the game should be in the menu next to the Ori games; with more than two games the tiles become a grid and, past six, Previous and Next appear and work from the headset. Choose the new game: it should start, appear in 3D, play with the controllers, and come back to the menu when you quit, with its own settings file `flattodepth-<id>.ini`. Unplug nothing, but check a game that is mid-download is not offered. If this works for a game other than Ori, that is the first real test of the catalog idea: please say which game.

10. Tools, curve, glow, float window and rumble (all new, none yet seen in a headset). With a game showing, point just under the screen: the round tools button should appear left of the bar; press it, or hold both grips and press B, and the panel should open in front of you. Point at a button: it brightens and the controller clicks. **Shortcuts:** with the game as the desktop's front window, press Convergence, HUD depth and HUD: the picture should change as it does with F1/F2/F3 on a keyboard, and the panel's top line should say it was sent. Then bring another window to the front and press one again: it must say the game window is not in front and change nothing. **Swap eyes:** press it, and again, and check the depth flips and returns; also both grips + X; restart and check it was saved. **Curved screen:** if the log has no `XR_KHR_composition_layer_cylinder` the button is dimmed; otherwise cycle Low, Medium, High and check the screen bends round you at the distance it was, the bar and handle sit on the curve, pointing and resizing still work, and moving the screen keeps it centred on you. If the curved screen is at the wrong distance set `curve_pose_at_axis=1`. **Glow:** the room around the screen should take the colours of the picture, softly, with no flicker; check that `Ambient glow sampling` appears in the log (if it says it is unavailable, the GPU cannot build mip levels for the export's format). **Float window:** cycle Low, Medium, High in a scene with something popping out near the edge and see whether the edge cut-off bothers you less; each step hides a little more of the picture. **Rumble:** play to a hit or a shove and feel the controllers; `game_rumble_writes` in the log should grow when the game rumbles; try `split=1`. If there is no vibration the log says why.


Future positional diorama perspective has not been implemented. The current screen uses normal OpenXR head tracking and preserves Geo-11 binocular disparity, without changing the game camera.
